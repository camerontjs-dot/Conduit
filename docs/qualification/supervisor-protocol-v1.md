# Internal supervisor protocol v1 — local development candidate

This successor closes S1 design findings for implementation and development probes on the current macOS 27.0/26A428 arm64 host. It does not qualify macOS 15.7.9, production commands, containment, an installed app or a trial. R3 is unchanged. Only the internal disposable-fixture initializer may select the helper. No request, environment switch, settings or public initializer can select it.

## Ownership

One unprivileged, single-thread C supervisor S sets SIGCHLD to default (no SA_NOCLDWAIT), unblocks signals, ignores SIGPIPE, calls setsid before creating one direct child R, and alone waits for R. S has no Foundation, SwiftTerm, threads, signal-handler reaper or generic wait(-1). App waits only for S. R is the same executable in stub role, created with a separate PGID=R and SID=S; it creates no child before GO, reports actual PID/PGID/SID/PPID, then execs payload in place. Spawn resets stub signals/mask including SIGPIPE. No caller-supplied numeric signal target is accepted. Outside-session ordinary setpgid join is excluded; descendants can escape and hostile same-user/privileged interference is excluded.

Before successful spawn there is no valid target. Before validated READY only the exact successfully spawned child may be signalled, under continuous custody. After actual parent/session/group validation only -R may be signalled. waitid(P_PID,R,WEXITED|WNOHANG|WNOWAIT) observes custody/root outcome. EINTR retries on a later bounded turn; any other error closes authority forever. Exclusivity is an invariant, not an atomic waitid+kill promise. Before final exact-child reap, close all nonzero signalling. Never adopt persisted PIDs after loss/restart.

## Durable order

App retains the existing permanent stable-operation `.reserved` marker and exact request/project binding. App persists queued and started/launch-intent before spawning S. Attempt nonce is allocated once in that receipt. Same ID never allocates a second nonce or helper after uncertainty. Initial v2 fixtures use a separate fresh store; v1 historical receipts remain readable and read-only.

S receives pinned store-directory FD 5 and cwd-directory FD 6. Before R, S exclusively creates `<operationID>.launch-claim` (O_EXCL, O_NOFOLLOW, mode0600), writes nonce, fsyncs file and directory, closes store descriptors. Existing/ambiguous claim refuses R. No claim is removed. No receipt filesystem I/O occurs in S after R exists. App is the sole mutable receipt writer, serialized by service lock and consecutive S event revision. v2 persisted receipts keep capacity acknowledgement false; only this live owner sets its in-memory acknowledgement true after final persistence returns successfully. A new owner refuses new IDs when any prior v2 launch claim is present; prior IDs remain readable/replayable without execution. Root facts are immutable. Failed final persistence retains capacity; replay never implies durable completion. Prelaunch fsync can stall: no payload and no hard filesystem deadline claim.

## Descriptor and wire contract

S argv: `--supervise NONCE OPERATION_ID TIMEOUT_MS -- ABSOLUTE_PAYLOAD ARGS...`. Nonce is 32 lowercase hex (identity, not secret/grant); operation ID uses existing restricted ASCII identity. Timeout is 1..5000ms for this initial supervisor candidate. S receives 0=/dev/null, 1/2=payload output pipes, 3=app control read, 4=status write, 5=store directory, 6=cwd directory; all other inherited descriptors close. It retains only relevant pipe ends. S does not write diagnostics to payload stdout/stderr. Payload receives only stdin/stdout/stderr, literal argv, cwd and fixed PATH=/usr/bin:/bin, LANG=C. Control/status/store/setup FDs close before exec.

Control and status are separate anonymous pipes; payload stdout/stderr are two additional independent pipes drained by the app. Payload backpressure may block payload writes; it cannot block S control. S's loop never drains an unbounded output stream. Control and status are nonblocking. Frames are ASCII lines no longer than 256 bytes including newline, with no NUL and exact fields/no trailing fields. Incoming buffer <=512 bytes; status queue <=4096 bytes; <=8 control frames and bounded write work per turn; poll interval <=10ms. Partial reads/writes retain their cursor, EINTR/EAGAIN defer without spinning. Malformed/oversize/unknown identity closes the protocol and initiates independently caused cleanup if owned. SIGPIPE is ignored only by S, EPIPE is channel loss. A full status queue causes channel-loss cleanup, not unbounded buffering or false delivered acknowledgement.

App commands: `CDS1 NONCE 1 GO\n`, `CDS1 NONCE 2 CANCEL\n`, `CDS1 NONCE 3 OBSERVE\n`. Fixed command sequence slots bound duplicate state. GO once, duplicate GO returns its disposition; CANCEL accepted once while open (including before GO), duplicates return original disposition without signals/deadline extension; OBSERVE returns current facts. CANCEL before GO prevents GO and cleans stub. GO after closure never releases payload. No arbitrary sequence allocation/target/action.

S status: `CDS1 NONCE REV TYPE INTEGER_FIELDS...\n`, REV starts1 and increases for each frame. Types: READY(rootPID,PGID,SID); GO(committed0or1); CANCEL(accepted0or1); ROOT(exitCode,signal) where -1 denotes unavailable exitCode; CLOSED(); FINAL(rootObserved,reaped,groupAbsent,cause,exitCode,signal); ERROR(errno). Numeric cause:0 natural,1 cancellation,2 timeout,3 disconnect,4 protocol/setup,5 ownership loss. Add no other wire types without revising this document. Replayed dispositions get a new event revision; old root facts never change. OBSERVE emits GO/CANCEL as applicable and ROOT if known, not a new execution. Final requires CLOSED earlier in revision order. EOF without FINAL is unknown. SIGPIPE, EOF or event loss never means payload completion.

## State/deadlines

BOOT -> CLAIM_SYNC -> STAGED -> READY -> GO_COMMITTED -> ACTIVE -> CLEANUP -> SIGNALS_CLOSED -> FINAL; failure can enter CLEANUP/LOST from earlier states. S commits GO only after READY and before observed channel loss/cancel/closure, immediately before sending the one-byte stub release. The commit is the launch linearization point. A buffered GO can commit before EOF is observed after app death: may-have-run is honest; no atomic parent-alive+exec claim. Stub executes once or reports exit failure; closed setup pipe is not proof of successful payload execution.

After claim sync, setup/GO has a 2000ms deadline. Stub waits at most2000ms for GO. Active timeout starts at GO commit and is at most5000ms. Root exit is observed without reaping and retains a250ms late-cancel window. A cancel during that window starts TERM, then KILL after500ms if custody holds; natural root code is retained separately. Cleanup control ends no later than2000ms after its first termination request, and no later than2000ms after observed root exit if earlier. No progress/duplicate resets a deadline. After KILL and observed root exit, close signals, reap once, observe group absence read-only until cleanup deadline. With no cancel during natural window, close/reap and probe boundedly; a remaining group is unknown. Signal0 errno EPERM vs ESRCH is retained in interpretation; only ESRCH after reap supports original-group absence, not escaped-descendant absence. No indefinite final wait. Final flush <=100ms; delivery loss is unknown. These are control budgets, not hard real-time guarantees.
