# Qualification input targeting

#65 is owned by the operator-surface lane. The original possible Antigravity
input remains UNKNOWN. These controls do not establish its historical effect.

Use the typed Session API with a full task ID when it exercises the intended
boundary. Keep its write gate, runtime readiness and delivery/acceptance axes
separate. A provider finishing or a successful HTTP response does not prove
the task's outcome. Do not use the normal operator listener/state as apparatus.

For a UI-only boundary, resolve the owned candidate process and owning window,
then resolve the exact semantic accessibility identifier immediately before
activation. Read the current identifier, role, enabled state and full target
identity again on the resolved element. Require exactly one match. Discard the
element after use. Missing, duplicate, changed, disabled or unverifiable identity
is BLOCKED/NOT_RUN; never fall back to a row number, stale index, agent name,
shortened task ID, typing or Enter.

Stable identifiers come from `OperatorControlIdentifier`:

- Settings: `conduit.controls.settings`; its surface and Done are
  `conduit.settings.surface` and `conduit.settings.done`.
- Task selection: `conduit.task.<full-lowercase-task-UUID>`.
- Runtime input: full task UUID (or explicit `unbound`), runtime UUID and runtime
  attempt UUID, followed by the UTF-8 hexadecimal control component.
- Strip choices and keys, output-event menu choices/keys and composer Send/editor
  have distinct control components. Output controls include the full event UUID.
- A composer without a runtime has a separate task/project identifier. That
  identifier grants no task creation or execution authority.

Conduit rechecks current project, task, active runtime, exact runtime attempt,
ownership and unambiguous live binding before menu input. A stale composer
callback retains its draft instead of redirecting it. Conversation key routing
also requires its actual mounted window to be key, with no sheet or modal window; the incoming event must belong to that same window.
Explicitly unbound legacy runtimes retain exact runtime/attempt targeting.

The app cannot infer the intended Settings action if an external client presses
a different currently valid input control. Unique semantic re-resolution in the
automation is part of the boundary; identifiers alone do not make stale
positional automation safe.

Binds: qualifiers and automation activating candidate UI controls.
Tier: T0 for the procedure; product dispatch checks are covered by native/Core
regressions, not by an enforcement claim over external automation.
Check: inspect the actual accessibility surface and preserve exact PID/window/
control/task/runtime/attempt receipts; duplicate/stale negative controls.
Escape: use the equivalent typed API, or return BLOCKED with the unavailable
identity/accessibility prerequisite. Do not enable permissions or operator
write authority just to make a qualification pass.

Local acceptance of mounted AppModel, Session API and accessibility controls
remains distinct from Core tests and disposable component hosts. Use the #87
owned-root/port contract for a mounted candidate; never install, adopt or
mutate an unrelated operator task as a test fixture.
