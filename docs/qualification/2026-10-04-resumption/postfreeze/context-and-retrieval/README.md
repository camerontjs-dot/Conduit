Main already contains the typed authority model, Context compiler, structured
deduplication, budget assessment, handoff rendering and explicit snapshot
store. #132 adds retained create/revise/retire definitions with unresolved
dynamic rules. It does not mount a UI or Session API caller.

The remaining product work should consume those existing owners. It needs an
inspectable manifest showing source identity, authority, inclusion reasons,
representation, freshness, omission and budget uncertainty; an explicit
definition-versus-handoff-snapshot distinction; and an attachment operation
bound to the chosen task. These are ordinary adopted obligations.

Current ContextStackView renders the bundle and a known token subtotal. It
does not take the richer ContextBudgetSummary/ContextSet manifest as input.
A new mounted caller must retain unknown cost/capacity/reservation states.
The source contains no measured latency result; actual responsiveness needs
separate local cold/warm timing and a predeclared target if a pass/fail
judgment is wanted.

The review found one bounded source repair that can advance independently:

ID with source `a|b` and revision `c`, then source `a` and revision
`b|c`, is different but has the same old representation. The separate
main-based delta candidate compares typed fields while retaining the public
fingerprint representation and existing presentation exclusions.

Duplicate stable IDs are a separate source pressure case. The current differ
uses Dictionary(uniqueKeysWithValues:), while a decoded bundle can contain
repeated IDs. The appropriate diagnostic must preserve its actual outcome;
this packet does not invent a first-wins, last-wins or duplicate-admission
