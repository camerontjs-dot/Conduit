## Candidate 123: owned qualification instance

The port is a canonical decimal integer in 18750–18849. Mixed, absent-half, malformed or invalid qualification configuration refuses startup with exit 78 rather than falling back to the ordinary listener or stores. A listener collision reports failure without selecting another port.

The root is an absolute POSIX-canonical path, outside operator home/state, with no symlink ancestors. A new/empty root becomes typed and owned; reopening requires a valid typed marker, ownership and a regular unlinked tree. Foreign state, symlinks, hard-linked files and nonregular entries are refused. Inspection is bounded at 10,000 entries. An exclusive lease prevents simultaneous adoption of one root.

Qualification state includes settings, preferences, API token, adapter-thread records, task/conversation/work logs, attachments, context bundles and snapshots. All such state remains under the owned root. Existing `HOME` and `CODEX_HOME` meanings are preserved. Operator state must not be read as fallback or modified.

A fresh root has no configured MainFrame and does not enable its listener automatically. Its settings explicitly enable the API. A selected directly readable MainFrame fixture must be inside the owned root; it requires no operator bookmark. Missing/unavailable fixture readiness is not ready; a valid selected readable fixture supports a native `/readyz` 200-ready response and its project inventory. API writes remain disabled by default.

Qualification startup does not perform implicit login-shell, shared tmux, provider/account/model/resource, tunnel, default OpenCode database or operator-home discovery. An OpenCode observation requires an explicitly selected regular owned database inside the root. Context/command/provider helper fallbacks cannot silently reach operator stores. No real provider turn or hosted-account authority follows from selecting qualification mode.

The claim to test is bounded actual-app isolation and truthful readiness/refusal, including negative controls and process/cache/resource custody. A root path alone does not prove every subprocess or compiler cache is owned. Ordinary app semantics must remain intact, but do not launch an unisolated app against operator state to test that claim.
